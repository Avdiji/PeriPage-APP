PeriPage-APP — Architecture & File Structure
=============================================
Flutter rewrite of the PeriPage printer app (reference: com.ileadtek.peripage v6.10.12).
Targets : Android + Windows          Flutter: 3.47.8 (pinned in .fvmrc)
Backend : none (offline, local storage only)
Style   : Clean Architecture, feature-first core, Riverpod (MVVM-ish),
          same conventions as github.com/Avdiji/flutter_supabase_login

Three features:

  1. Device   — first-run setup (find, connect, save as default), live status
                (ready / printing / no paper / low battery …) with a progress bar for
                the running print, printer info, device defaults.
  2. Draft    — pick any printable file (PNG, JPG, JPEG, WEBP, BMP, GIF, PDF), adjust
                settings with a live preview, print.
  3. History  — every printed file with the exact settings it was printed with;
                one tap reprints it, tapping the row opens it as a new draft.


1. LAYERS & DEPENDENCY RULES
----------------------------

  presentation/            Screens & widgets. Watch providers, never touch services.
        |
  core/<feature>/state/    Riverpod notifiers = view models.
        |
  core/<feature>/domain/   Entities, repository interfaces, use cases. Pure Dart.
        ^
  core/<feature>/data/     Repository implementations. Map service DTOs -> entities.
        |
  services/                Transport, protocol, imaging, files, local storage.

  - Arrows = import direction. domain/ imports nothing outside itself.
  - All dependencies are Riverpod providers; the platform transport (Android SPP /
    Windows COM) is chosen in main.dart via a ProviderScope override.
  - services/protocol and services/imaging are pure Dart and unit-tested.

3. FLOWS
--------

  First run
    no saved printer -> Setup: list paired printers (PeriPage_*, PPG_*, SQAI_PP_*)
    -> connect -> read model/firmware/serial -> save as default -> apply defaults
    (density, paper, auto-off) -> read battery -> shell

  Draft -> Print
    pick -> copy into app storage -> per page: load (PDF rendered at 2× width)
    -> rotate/scale to head width -> dither (isolate) -> preview
    Print: density, then per page and copy:
       10 FF FE 01 | 12 × 00 | 1D 76 30 raster | 1B 4A feed | 10 FF FE 45
    written in 1024-byte chunks; progress = bytes written / total
    -> on success a HistoryEntry (file copy + settings + thumbnail) is stored

  Status
    every 5 s while connected and idle: 10 FF 40 (status) + 10 FF 50 F1 (battery)
    while a job runs the status is "Printing" with the job's progress

  History
    Print   -> rebuilds the identical job (ReprintUseCase) -> same print path
    Row tap -> opens the file in Draft with its settings


4. PROTOCOL SUMMARY (details -> docs/protocol.md)
-------------------------------------------------

  Model / FW / SN           10 FF 20 F0 / 10 FF 20 F1 / 10 FF 20 F2
  Battery                   10 FF 50 F1      -> 2 bytes, second = percent
  Status                    10 FF 40         -> 00 idle, 01 busy, 04 no paper, 08 low bat.
  Density                   10 FF 10 00 <0|1|2>
  Paper type                10 FF 10 03 <0 roll | 2 label>
  Auto-off                  10 FF 12 <hi> <lo>   (minutes)
  Start / end print         10 FF FE 01  …  10 FF FE 45
  Feed n dots               1B 4A <n>
  Raster                    1D 76 30 00 <bytesPerRow LE16> <height LE16> + data
  Ack                       "OK" (4F 4B)

  KNOWN GAP: models the official app drives with compressed raster
  (1F 00 … + native libCode.so: A8/A9/A40/P40/H2/Q9 families …) receive GS v 0
  here; whether their firmware accepts it is untested. The Device view says so.
